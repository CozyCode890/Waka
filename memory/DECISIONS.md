# Decisions

Format: `D-NNN | yyyy-mm-dd | decision | why | rejected`

D-001 | 2026-10-06 | Project memory lives in `D:\Weka-GUI\memory\`, tracked by git | memory travels with the code, every automatic edit becomes a reviewable diff, and the user can open RULES.md themselves | Claude Code's native per-project store, which sits outside the repo and whose one-fact-per-file convention costs one read per fact; mirroring into both, which guarantees two sources of truth with no rule to arbitrate between them

D-002 | 2026-10-06 | §ROUTER lives in CLAUDE.md; source read-depth lives in SOURCE.md | the router must be free to consult, so it belongs in the only auto-loaded file, while the source map grows with `src\` and the auto-loaded file must not grow | a single POLICY.md for criteria 8+9+10, which costs a ~2.3k-token read before any work can start and is simply skipped by sessions in a hurry; putting everything in CLAUDE.md, which pushes it past 200 lines until it gets skimmed

D-003 | 2026-10-06 | Every memory file is written in English | the facts are about Java identifiers, so English keeps a grep for a class name working; routing keywords stay short | all-Vietnamese, where a `[gotcha]` about a Weka API would not be found by grepping its English class name; mixing languages inside a line, which makes diffs noisy

D-004 | 2026-10-06 | Stage detail is generated just-in-time — one CURRENT.md, for the current or next stage only | detail written after the previous stage's real outcome is far less often wrong, and the read cost stays flat however many stages the project grows | pre-generating two stages ahead; a `stages\` directory with every stage detailed up front, where most content goes stale before it is used and is wrong *confidently*

D-005 | 2026-10-06 | One SessionStart hook that prints §STATE; no PostToolUse hook | it recovers the state cursor when a long session's compaction drops CLAUDE.md out of context, for about five lines of config and no interruption to any write | a PostToolUse write-log, since `git diff` already answers "what did you change" and an append nothing enforces becomes a partial record that looks authoritative; no hooks at all, which would leave the whole system resting on compliance alone

D-006 | 2026-10-06 | PLAN.md and STAGES.md stay separate files | they have opposite edit rhythms — the plan must freeze, stage status changes several times per session — and a clean authority boundary is what gives the §AUTHORITY table any force | one file with a stage table at the end, where Claude would be writing into the same file that holds the project's scope, and "the plan is inviolable" stops meaning anything

D-007 | 2026-10-06 | Decisions get their own append-only DECISIONS.md rather than a `[dec]` tag inside FACTS.md | a decision carries a rejected alternative and a fact does not, and append-only is natural here while facts stay editable | folding them into FACTS.md, which saves a file and a read but mixes two write modes in one file

D-008 | 2026-10-06 | SESSION.md keeps exactly two blocks, and the third may only be dropped after its still-true lines are promoted into FACTS.md | forgetting is deliberate and read cost stays flat, with a funnel into long-term memory so nothing useful is lost silently | one file per session in a `log\` directory, which grows without bound and which no router row reads

D-009 | 2026-10-06 | UI toolkit is JavaFX + AtlantaFX, not Swing + FlatLaf | real CSS lets the Fluent token system from the design reference port almost 1:1, scrolling and animation are first-class, and translucency works today; we are replacing Weka's panels rather than embedding them, so the usual "Weka is Swing" argument does not apply | Swing + FlatLaf, which is cheaper and has better accessibility but gives no Mica without going undecorated and has no animation story; Compose Desktop, which has the best motion but is Material not Fluent, forces Kotlin + Gradle, and does not work with Windows Narrator; SWT, which is Windows-10-era native, not Fluent

D-010 | 2026-10-06 | Pin JavaFX 27 (non-LTS) on JDK 25 LTS | three hard blockers on JavaFX 25, not preferences: the D3D9 `BackBufferFormat = D3DFMT_UNKNOWN` fix that makes UNIFIED + Mica run on the fast painter, the large-table selection and sort fixes, and `ConditionalFeature.EXTENDED_WINDOW`; JavaFX is a dependency, not a platform, so the March 2027 move to 28 is a coordinate bump while the JDK stays on an LTS | JavaFX 25 LTS with AtlantaFX 2.1.0, which has a support window to ~2030 but would mean a 60fps cap or a preview flag for the features we need; JDK 27, which is non-LTS with no upside here

D-011 | 2026-10-06 | GPLv3-or-later, public repository, Weka linked in-process | Weka is GPL-3.0-or-later with no linking exception, so linking forces it; in exchange we get typed `Instances`/`Evaluation`/`Package` objects, the whole headless package-manager API, and no stdout parsing | a closed-source app that only spawns the CLI and does not bundle weka.jar, which is the sole way to stay proprietary but costs regex-parsing confusion matrices out of text, a JVM start per command, and the typed package API

D-012 | 2026-10-06 | Rail = app modes; datasets open as document tabs; a segmented bar inside a tab switches Preprocess/Classify/Cluster/Associate/Select/Visualize | keeps Explorer's vocabulary exactly where people expect it while adding the one thing Explorer cannot do — several datasets open and comparable at once; the segmented control is also what the design reference uses for in-page navigation | putting the Weka tasks on the rail itself, which is simpler and closer to the reference app but allows only one active dataset and wastes document tabs; a pure VS Code shape driving everything from the command palette, where an Explorer user would never find "Classify"

D-013 | 2026-10-06 | Rail and side panel default to the RIGHT edge, swappable by setting | matches the user's own daily VS Code configuration (`workbench.sideBar.location: right`), so the shell feels like the tool they already drive | the left edge, which is what the rest of the world and the design reference do — kept as a setting rather than a default

D-014 | 2026-10-06 | `StageStyle.UNIFIED` + Mica now; the native title bar stays, recoloured via `DWMWA_CAPTION_COLOR`; a custom header waits for JavaFX 28 | these are mutually exclusive today, because `GlassScene.getClearColor()` returns an opaque white for every style except TRANSPARENT and UNIFIED; UNIFIED keeps the fast presenting painter and costs ~15 lines, while a custom header would have to be built twice once PR openjdk/jfx#2048 lands | `StageStyle.EXTENDED` + `HeaderBar` now, which gives a genuine VS Code header with working snap layouts but forfeits translucency entirely; building both behind a setting, which doubles stage-1 scene work for a finish, not a layout

D-015 | 2026-10-06 | Pin `weka-stable` 3.8.7 | it is what the official installers ship and what most repository packages are built and tested against, and the stable line takes bugfixes only, which matters because we lean hard on internal API (`OptionHandler`, `Capabilities`, `WekaPackageManager`) | `weka-dev` 3.9.7, which matches the 3.9.6 already installed on this machine and reads its old models, but whose API can shift between dev releases; supporting both behind a compatibility layer, which doubles the test surface for v1

D-016 | 2026-10-06 | Maven, three modules `core` → `app` → `dist`, with JavaFX at `provided` scope and the application on the classpath; jlink images only JDK + `javafx.*` modules | the only real capability gap favouring Gradle is badass-jlink's merged-module machinery, which exists to drag non-modular jars into a modular link — an architecture we are deliberately not using, since Weka resolves classes by name from props files and loads package jars at runtime | Gradle with badass-jlink, correct only if we went genuinely modular, which is the wrong goal here; making the app a JPMS module, which fights Weka's reflection for no benefit

D-017 | 2026-10-06 | The bottom panel is a tabbed container of output providers; ship a plain console pane first, add JediTermFX later as an optional module | ~95% of "I want a terminal" here is watch, scroll, search, copy, save, kill — none of which needs a VT emulator; designing the panel as providers from day one makes the real terminal one more tab rather than a rewrite | JediTerm inside a SwingNode, which drags AWT into the runtime image and carries known Tab/Escape, popup and focus defects; starting with a PTY at all, which front-loads native dependencies before the layout is even approved

D-018 | 2026-10-06 | Share the standard `%USERPROFILE%\wekafiles` rather than forking `WEKA_HOME`, and surface the effective values in Settings | forking it would make the user's already-installed packages vanish from our package manager, which is a far nastier surprise than inheriting their props files | our own per-app WEKA_HOME, which is cleaner and isolates us from a stale `DatabaseUtils.props` but hides their existing packages

D-019 | 2026-10-06 | `jpackage --type app-image` then Inno Setup 7 for the installer, per-user, no admin | app-image needs nothing but the JDK and gives a portable build for free; Inno adds LZMA2 compression that matters for a bundled JRE, per-user installs with no UAC, dark-mode installer UI, signed uninstallers, and `AppMutex`/`CloseApplications`, which is the hard half of self-updating on Windows | jpackage's own MSI/EXE, which needs WiX plus the .NET SDK on the build machine and has an unthemeable UI; MSIX, whose container fights an app whose job is spawning child processes; Velopack, which still has no JVM SDK

D-020 | 2026-10-06 | Add a `decide` router row reading §STATE, CURRENT, STAGES, DECISIONS and PLAN | "where am I and what must I choose" recurs at every stage boundary and matched no row, so the first session to hit it declared `where` and then read the kickoff set anyway; PLAN is in the set because a row whose job is recommending must see the eleven NON-goals or it will eventually recommend one | widening `where` to also allow CURRENT.md §Open questions, which costs no new line but still cannot explain the choices themselves; leaving it alone, which re-pays the wrong-row cost once per stage boundary, seven more times

D-021 | 2026-10-07 | UI is graded before it is built: one HTML mockup per wave under `design\`, published to a stable artifact URL, carrying numbered `G-NNN` marks the user answers, with the verdicts frozen into DESIGN.md | JavaFX uses real CSS, so a token-disciplined mockup is a near 1:1 spec rather than a drawing, and it iterates in seconds; a JavaFX prototype iterates in minutes and cannot exist until S00+S01 are done, which would mean grading the layout after logic is welded to it — the exact failure PLAN says the stage order exists to prevent | a JavaFX prototype first, perfectly faithful but arriving too late to change anything cheaply; static SVG images, which cannot show hover, empty states, a theme switch or Mica off

D-022 | 2026-10-07 | Terminal is a named fourth provider in the bottom panel from v1, shipping as a plain console — run, watch, search, copy, kill — not a VT emulator | the user asked for it directly and data-science work expects a terminal in the window; D-017 already designed the panel so a terminal is one more tab rather than a rewrite, so naming it now costs one tab and one PLAN line and keeps the VT question open | a real PTY in v1 via JediTermFX + pty4j, which drags AWT into the runtime image and carries the Tab/Escape/focus defects D-017 rejected; leaving it out entirely, which hides the one capability the provider design was explicitly built to accept

D-023 | 2026-10-07 | Everything in the repo is English and written to be read by a learner — identifiers, comments, file and directory names, asset names, config keys and console output — in plain words a student already knows, with no clipped abbreviations, and where two forms do the same job the clearer one wins over the shorter one | the user is building this to re-read, check and hand on, so the inheriting reader is the real audience rather than the author's own typing speed; and an English identifier is the only kind a later session can grep for next to Weka's own API names | Vietnamese identifiers or comments, which break that grep and make every diff a two-language read; English identifiers under Vietnamese comments, which splits each file in two and still cannot be searched; terse idiomatic Java tuned for the author, cheap to write once and unreadable for exactly the person this code exists for

D-024 | 2026-10-07 | Every UI string goes through a language pack from the first screen; v1 ships exactly one pack, English | retrofitting this after the screens exist means reopening every FXML and controller, while doing it now costs a resource bundle and one lookup call per string; Vietnamese is a separate project, so v1 must not carry a half-filled second pack | hard-coded English strings with a promise to extract them later, which is how a project ends up never doing it; shipping a Vietnamese pack in v1 too, which doubles every string review for an audience that does not exist yet

D-025 | 2026-10-07 | The app is named **Waka** — display name `Waka`, Maven artifactId `waka`, install dir `Waka`, window title `Waka`, GitHub repo `Waka`; the local working copy stays `D:\Weka-GUI` | the name says what the app is a front end for without claiming to be it, and a folder name is only where the files sit, so renaming the working copy would cost a git remote fix and four path lines in memory for nothing | all-lowercase `waka`, which Windows shows in Start Menu, taskbar and installer where it reads as a typo rather than a choice; renaming the working copy to D:\Waka, which touches D-001 and four FACTS lines and buys no capability

D-026 | 2026-10-07 | An About screen names Weka upstream — the University of Waikato Machine Learning Group, the authors, the distributor, the licence and the exact linked weka-stable version — and carries a real music player for "Waka Waka", reading an audio file the user drops into `assets/audio/`; the repo ships that directory empty with a README, the button opens the official video in the browser when no file is present, and `javafx.media` joins the runtime image | GPLv3 requires the attribution and licence notice to be reachable from the running program, so this screen is a compliance obligation before it is decoration, and it is the honest answer to "whose algorithms are these"; shipping a copyrighted master recording inside a public GPLv3 repo would make the whole distribution non-redistributable, which is the one thing GPLv3 does not allow | an About box holding only our own version string, which leaves the GPL notice nowhere in the running app; the LICENSE file as the only notice, which the installed app's user never opens; bundling the mp3, the only way everyone hears it out of the box and also a licence violation and a takedown risk; a link-only About, which saves ~5MB and `javafx.media` but drops the feature outright

D-027 | 2026-10-07 | No panel in this app is a modal dialog. The options editor, the decision-tree viewer and everything Explorer would have opened as a dialog is content hosted in the window like VS Code's Settings, reparentable at runtime between three hosts — in-window panel, its own window, or a document tab — with close, pop-out and open-as-tab controls on its own header | the options editor is the screen people live inside while tuning a scheme, and a modal dialog blocks the very dataset they are tuning against; building one host that can reparent is also what makes "two schemes open side by side" possible at all, which is a PLAN success test | modal dialogs like the GenericObjectEditor, the single worst thing about the Explorer and a stated reason this project exists; a non-modal dialog window only, which unblocks the UI but can never dock back into the tab being worked in; tabs only, which cannot float over the data while you read it

D-028 | 2026-10-07 | The Weka Output provider is a list of collapsible run blocks, not one append-only text buffer; every block header states the dataset file, the scheme, the full option string and the start time | the only question anyone scrolling that panel is asking is "which run am I looking at", and a flat buffer makes them hunt for the boundary; blocks also hand us collapse, copy-one-run and jump-to-run for free, and they are the same unit the run history in PLAN is keyed on | one scrolling TextArea like the Explorer's, simpler and already verbatim-correct but leaving two runs indistinguishable the moment they scroll past; printing a header line into the same flat buffer, which labels the run but still cannot collapse or copy just that run

D-029 | 2026-10-07 | Maven comes from scoop (3.10.0, per-user), and JDK 25 is selected through a USER-scope `JAVA_HOME` while Machine `JAVA_HOME` and Machine `PATH` stay on JDK 21 | winget publishes no `Apache.Maven` package at all, so the approved "winget both" plan was impossible for Maven; and Windows appends User PATH after Machine PATH, so a User entry can never shadow the Machine-scope `jdk-21\bin` already there — pointing `JAVA_HOME` at 25 is the only no-admin route, and Maven honours `JAVA_HOME`, so every build runs on 25 while `java` in a bare shell still answers 21 | editing Machine `JAVA_HOME` and Machine `PATH`, which makes `java -version` answer 25 in every shell but costs a UAC elevation and silently takes JDK 21 off the PATH for every other tool on this machine; a `~\.m2\toolchains.xml`, which changes nothing machine-wide but hides the JDK choice in a file outside the repo that S01's jpackage would then have to be pointed at by hand; unzipping the Apache binary by hand, which works and depends on nothing but makes every future Maven upgrade a step somebody has to remember

D-030 | 2026-10-08 | GUI tests drive a real JavaFX stage parked off the desktop at -4000,-4000, and bringing any window onto the visible screen needs the user's permission, asked in that session, every time | the user studies on this machine while the app is built, so a test run must never seize the screen; and the off-screen stage is the only hidden route that actually runs here, because `org.testfx:openjfx-monocle`'s newest release targets JDK 12 and cannot be trusted on JavaFX 27 | Monocle headless, which shows no window at all but would cost a task to discover it does not run, and could never test Mica or the native caption anyway; no automated GUI tests, which leaves S01's exit test 1 with no repeatable proof and finds every later regression by eye

D-031 | 2026-10-08 | Every shell surface is built in Java — one view class per region — and this project ships no FXML | D-027 requires the options editor and the tree viewer to be reparented at runtime between three hosts, which FXML cannot express, so an FXML codebase would still carry the Java that does the real work; and a renamed node becomes a compile error instead of a stack trace at launch | FXML + controllers, conventional and tree-readable with Scene Builder support, but runtime-only errors and the dynamic half written twice; a hybrid of FXML for static regions and Java for dynamic ones, which hands the inheriting reader two conventions to learn where D-023 asks for the clearer one

D-032 | 2026-10-08 | The keymap is its own user-editable file under `%APPDATA%\Waka\`; theme, accent, rail side and Mica state live in a separate internal store, and a hand-editable `settings.json` stays where PLAN put it, under "Later" | the exit test demands exactly one user-editable file — a keymap that can REMOVE a default binding — and PLAN is frozen with `settings.json` outside v1, so shipping it now would be a scope change dressed as a convenience, plus a file format we would owe stability to | one `settings.json` now covering everything, which is one loader instead of two and pulls a Later item into v1; keymap only with nothing else persisted, which resets theme and rail on every launch and makes "the app looks finished" impossible to grade

D-033 | 2026-10-08 | `core` declares `weka-stable` 3.8.7 from S01 onward even though S01 makes no Weka call | D-016 predicts the 17 illegal automatic module names cannot bite jpackage, because jlink images only JDK + `javafx.*` and weka rides the classpath; that prediction costs one dependency line to turn into evidence now, against rediscovering it in S03 on top of an engine, a run model and a history | leaving weka out until S02, which gives a smaller and faster S01 image and hides the one packaging risk S00 explicitly handed forward

D-034 | 2026-10-08 | The Mica code finds its window handle through `FindWindowW` on the window title; the `--add-exports` into `com.sun.glass.ui` is dropped | S00 proved both routes return the same handle, so the export buys nothing and every jpackage, jlink, Maven and IDE launch configuration stays one flag shorter for the life of the project | keeping `--add-exports`, which is the documented route and avoids depending on a window title, at the cost of a flag that must be repeated in five places and re-justified at every packaging change

D-035 | 2026-10-08 | Icons come from Ikonli's Feather pack, and the default accent stays DESIGN's locked `#4CC2FF` dark / `#005FB8` light rather than following the Windows accent | Feather is MIT, so it raises no question against a GPLv3 distribution, and it is the pack AtlantaFX's own samples are drawn with, so stroke weight already matches at 20px; and the Windows accent is frequently a colour that fails contrast against `--card`, which would let the OS decide whether this app is readable | hand-drawing ~12 SVG paths, which needs no dependency and no licence check but costs a day and drifts in stroke weight where five icons sit in a column on the rail; Microsoft's Fluent System Icons, a perfect match for Windows 11 and MIT, but with no Ikonli or JavaFX packaging, so the SVGs and their loader become ours to maintain; following the Windows accent, with or without a contrast floor, which is truer Fluent but adds a colour branch to test across light/dark × Mica on/off while the shell is still being framed

D-036 | 2026-10-08 | README.md is written in Vietnamese; every other file in the repo stays English, and the in-app UI still ships English only | D-003 and D-023 are about greppability — a `[gotcha]` must be findable by the Weka class name it is about, and an identifier must sit next to Weka's own API names — and a prose README has no identifiers to grep for; the README's reader is the author and the students around them, who are the one audience that is actually Vietnamese, while D-024 keeps the shipped UI English | an English README matching the rest of the repo, conventional for a public GitHub project and the obvious default, but addressed at a contributor who does not exist yet instead of the people who will actually open this; a bilingual README, which doubles the file and leaves two versions to drift apart the first time the roadmap changes
